audience: whoever rebuilds the Android package, uploads a release, or touches the site's /.well-known/
updated: 2026-10-05

> Current state and next action are NOT here — see [../STATUS.md](../STATUS.md). The decision to
> ship as a PWA wrapped in a TWA is in [../DECISIONS.md](../DECISIONS.md) (2026-09-28, 2026-10-05).

## What it is

The Android app is a **Trusted Web Activity (TWA)**: a ~1.4 MB shell that opens
<https://komavision.netlify.app> full-screen in Chrome, with no browser bar. There is **no second
codebase** — every web deploy updates the app instantly, and a new Play release is needed only when
the shell itself changes (name, icon, colours, package version).

The project lives in [`apps/android/`](../../apps/android/), generated by **Bubblewrap**
(`@bubblewrap/cli`) from `twa-manifest.json`. Never hand-edit the Gradle files: change
`twa-manifest.json` and regenerate.

## ⛔ The two one-way doors

1. **The package name `com.komavision.app` is permanent** (owner, 2026-10-05). Play never lets an
   app change it; a new name is a new app with zero installs and a new closed test.
2. **The upload key lives OUTSIDE the repo**, at `~/.komavision/upload.keystore` (alias
   `komavision`), its password in `~/.komavision/keystore-password.txt`. The repo is public, so the
   key must never enter it — `apps/android/.gitignore` refuses `*.keystore` / `*.jks` as a second
   lock. ⚠ **Back both files up off this Mac.** With Play App Signing a lost *upload* key can be reset
   through Play support, but that takes days.

## How the site proves it owns the app

Android only drops the browser bar if the site lists the app's signing fingerprint at
`/.well-known/assetlinks.json` (`apps/web/public/.well-known/`, typed in `_headers`). It lives in a
subdirectory, so `prune-dist.mjs`'s "no `.json` at the dist root" rule allows it.

✅ **It holds BOTH keys since 2026-10-10**: Play's app signing key (`5A:2E:A6…84:BB`, from Play
Console → *Google Play ile korunanlar → Uygulama imzalama*, a copy button, the value is not printed)
and the upload key (`0B:33:9F…4F:E7`). Play re-signs every install with ITS key, so without that
line an app installed from Play opened as a Chrome tab with an address bar — seen on the owner's
phone the same day. Google's own Digital Asset Links API lists both. ⚠ The console moved this page
in 2026: *Uygulama bütünlüğü* now only points to *Google Play ile korunanlar*.

## The system bars follow the PHONE, not the in-app switch

`twa-manifest.json` sets the status and navigation bars to the page's own ground — `#faf1e1` by day,
`#0c1426` at night (`theme.ts` `BROWSER_BAR`, tokens.css `--paper`) — and Android picks the pair
from the **system** dark mode. The app's own sun/moon switch cannot reach them: a reader who forces
dark inside a light phone gets an ivory navigation bar under a dark page. Accepted; the app's default
is the system setting anyway. ⚠ The browser-installed PWA (Add to Home screen) colours its
navigation bar from the manifest instead, which has no dark variant — it showed ivory under the dark
page on the owner's phone (2026-10-08). Not fixed there; the Play app replaces it.

## Rebuild

```bash
export BUBBLEWRAP_KEYSTORE_PASSWORD="$(cat ~/.komavision/keystore-password.txt)"
export BUBBLEWRAP_KEY_PASSWORD="$BUBBLEWRAP_KEYSTORE_PASSWORD"
cd apps/android
bubblewrap update        # bumps appVersionCode; Play refuses a code it has seen
nice -19 bubblewrap build --skipPwaValidation   # → app-release-bundle.aab (upload this)
```

⚠ Tooling traps met on 2026-10-05: Bubblewrap's `jdkPath` (in `~/.bubblewrap/config.json`) is the
`.jdk` folder, **not** `…/Contents/Home` (it appends that itself); its SDK check wants a `tools/`
folder, so Homebrew's `android-commandlinetools` needs `tools → cmdline-tools/latest` symlinked; and
it builds with build-tools **36.1.0**, which must be installed with `sdkmanager`. Target SDK is 36; **minSdkVersion must be ≥ 24** — Play refused the first upload at Bubblewrap's default of 21 (2026-10-10).

## The closed test — the real gate

A personal account opened after 2023-11-13 cannot publish to production until a **closed test has
had ≥12 testers opted in for 14 consecutive days**. If the count drops below 12, the 14 days restart.
Google also asks about the testers' use and feedback in the production application (reported by
tester-service blogs as checked more strictly since 2026 — not verified against Google's own text). So: recruit **15–20**, not 12; each one needs a Google account, joins
the tester list, opens the opt-in link, installs from Play, and keeps it installed for the 14 days.

## Store listing inputs

- Privacy policy URL: <https://komavision.netlify.app/privacy.html> — ⚠ same statement-of-fact
  contract as the footer ([../../apps/web/src/ui/strings.ts](../../apps/web/src/ui/strings.ts)).

- Data safety: no account, no ads, no data sold or shared; images processed and not stored;
  anonymous usage analytics (hashed daily, country/device/browser/OS); data in transit encrypted.
